# 本地菜谱速查页面

页面入口为 `/`，沿用 Nuxt 4、Vue 3、TypeScript、Tailwind CSS 4、petit-ui 和 Reka UI，不增加数据库或运行时服务端 API。站点标题仍为 Petit。页面消费[已校验的菜谱数据](../recipes.md)，不修改原始转录来迎合展示。

## 关于与来源说明

`/about` 保留一段非官方手册简介、简短来源、原站链接、两份来源图鉴、单独致谢和版权说明。菜谱资料来源只说明使用了两位作者的图鉴及用户提供的游戏截图与文字资料，不展开主体／补充关系、收录数量、问号处理、日期缺失或品质依据。两份图鉴放在同一区域；图片来源另设区域，简述 Wiki 与 TapTap 配图来源，并集中提供原站链接。特别致谢单独感谢图鉴作者、Petit Planet Wiki 社区和 TapTap 作者阿Zz，署名读取现有清单。版权文案说明权利归属、尊重原创及侵权反馈后的核实处理，不宣称已经获得授权或保证不侵权。

关于页先展示作为主体的明天攻略组 2026-09-24 图鉴，再展示作为补充的小铭同学 9 月 27 日图鉴，分别标注制作者与图片日期。小铭图未注明年份，只显示原文月日。雪菜图及配套归档已删除；9/23 旧图与独立游戏效果截图继续本地保存，不进入发布图片。点击两张图使用 Viewer.js 页内预览，支持滚轮／双指缩放、拖动、原尺寸、适应屏幕和切图；中文工具栏保留打开原图，作者与日期随切图更新。

图鉴预览直接接入 Viewer.js，不增加 Vue 封装依赖。核心仅在首次点击时动态加载，退出关于页销毁实例；静态页面和脚本不可用时仍保留原图链接。修饰键点击保留浏览器打开链接的行为，加载失败显示原图入口提示。预览支持 Esc 关闭、Tab 循环、键盘按钮操作与关闭后返回触发位置；尊重减少动态效果设置。为避免阅读大表格时误切图，触摸拖动和滚轮不切图，使用上一张／下一张按钮或左右方向键切换，首尾不循环。

共用导航和页脚提供关于入口。关于页支持直接访问及刷新；料理详情不再提供来源跳转或证据入口。首页与详情不增加明天攻略组署名文案，站点标题仍为 Petit。

当前收录明天主体的 94 道及小铭补充的五道秘制菜，共 99 道，已有 ID 保持稳定。采用优先级、问号、未知值及独立增益证据的边界见[数据约定](../recipes.md)与[补充图报告](../references/recipes/xiaoming-09-27.md)。

## 内容与交互

视觉使用 petit-ui 的奶油纸色、深褐文字和金黄选择状态，默认以图标网格展示菜谱，也可切换为连续配方列表。搜索反馈、配方悬停和详情面板开合采用短促过渡；减少动态效果设置下关闭动效。

所有屏宽仅保留统一搜索框，结果使用主内容完整宽度；不再提供分区、方式、食材、词条筛选面板或“搜索／筛选”模式切换。菜品分区继续在结果与详情中展示，不称为游戏内菜品等级。

- 主搜索框统一查找菜名、食材原文、已录入的料理词条与烹饪方式。菜名、食材和方式按关键词包含关系匹配，例如“榨汁”可命中“榨汁机”；词条支持部分文字匹配，例如“饮”可命中“饮品”，输入完整词条时优先精确匹配，避免仅因“荤素菜”包含“素菜”而误命中。空格分隔的多个词需要同时命中，可分别命中不同字段，例如“草莓 小麦 甜点 烤箱”或“榨汁机 饮 奶”；候选食材仍可查到，结果中的待确认状态保留，待确认或未说明的词条与烹饪方式不作为确定值参与搜索。不推断食材类别成员关系或库存是否足够制作。
- 旧链接中的单值或重复 `ingredient` 参数延续已有兼容规则，合并为搜索框中的可见关键词，去除重复词和空项。已停用的 `mode`、`region`、`method`、`tag`、`ingredients` 参数直接忽略，不转成额外条件。下一次编辑、清空搜索或排序时统一清除这些旧参数，仅保留当前 `q`、`sort` 及无关参数。
- 可按原图顺序或已知力气升降序排列；未知力气始终位于末尾。
- 搜索词与排序写入 `q`、`sort` URL 查询参数，支持刷新和浏览器导航。SSG 水合后再应用查询参数，避免静态 HTML 与客户端首帧不一致；初始化完成前禁用依赖脚本的控件，避免首次输入或点击丢失。搜索使用 Vue 原生 `v-model`，中文输入组合期间不更新结果。
- 连续输入和排序合并尚未完成的路由请求，避免丢失最近输入。查询参数更新保留当前锚点，从“回到搜索”进入后输入或清空不会滚回页顶。纯空白查询显示全部菜谱，不显示“搜索结果”标记；保留输入中的分隔空格，方便继续输入下一个关键词。
- 结果工具栏提供“图标／列表”视图切换，按钮有选中状态和可访问名称，初始化前禁用。每次进入或刷新页面默认图标视图；视图是当前页面的显示状态，不写入 URL。切换保留搜索、排序和结果顺序；清空搜索不改变排序或当前视图。
- 图标视图突出大图与品质底色，显示完整菜名、分区、品质文字、待确认状态、烹饪方式和力气。桌面按可用宽度排列，手机为两列；食材与效果通过同一详情入口查看。两种视图共用候选配图、图片失败占位和详情交互，不复制另一份菜谱对应关系。
- 列表显示菜品缩略图、原文、保留重复项的食材、烹饪方式、力气、效果或产出。食材槽位按[食材品质要求](../recipes.md#食材品质要求)显示底色及“需紫色／金色品质”文字；候选和未知项继续保留独立提示，无底色不补猜品质。
- 点击配方打开 Reka UI 模态详情，支持 Escape、焦点约束和关闭后返回触发按钮。
- 详情显示菜品大图、分区、菜品品质、有序食材及品质需求、烹饪方式、力气、词条、特殊效果名称与阶级、作用和次数／时长。保留问号食材、未知值和制作限制；自由烹饪只显示主体图写明的产出概率，具体效果未说明。配方来源、待核对信息、新旧图鉴对照、原图行与视觉线索、配图来源、品质依据及增益截图均不在详情展示；这些资料继续本地归档与校验。
- 列表与详情中，效果栏空白或斜杠的非自由烹饪菜品按用户约定显示“无特殊效果”，不再追加“未说明特殊效果”。这只是展示文案，来源空白仍保留 `not-stated`，斜杠保留 `unresolved`；未知、待确认效果与自由烹饪产出继续分别表达。
- 没有匹配时提示更换菜名、食材、词条或烹饪方式，并提供“清除搜索条件”。清空后显示全部菜谱，已停用的旧参数不会重新生效。

## 菜品配图

99 道中已有 94 道候选配图，新增五道秘制菜显示“暂无图片”，仍能打开详情：87 条使用 Wiki 原始 PNG，7 条使用六张 TapTap 完整攻略 JPEG 中的对应区域。两类原文件仍按[素材索引](../references/recipes/dish-image-candidates.md)分目录存放，图片显示不改变配方事实与游戏验证状态。

- `shared/recipes/images.ts` 从 Wiki 与 TapTap 清单读取候选，经 Zod 校验；旧版候选按菜谱的 `previousRecipeId` 延续，新候选直接引用当前 ID。清单保留原始核对位置，不按新的行号配图；不另存第二份菜谱与文件的对应表。
- 新增的梦幻金玉满堂饭、梦幻草莓奶蛋糕、梦幻星莓漫游派、梦幻番茄汤汁面使用已核对的 TapTap 同名图标区域，保留候选状态和图中行号。
- TapTap 清单的 `targetRecipes[].displayRegion` 是原图像素坐标 `{ x, y, width, height }`，左上角为原点，仅用于 CSS 显示范围。一张原图可关联多道菜，七个区域均为 150 × 150；原 JPEG 没有裁切、重绘或覆盖。完整攻略图连同作者署名保留在本地来源目录，关于页集中提供原站链接。
- `modules/recipe-image-assets.ts` 在 Nuxt 准备与构建时，按 `shared/recipes/images.ts` 中当前候选使用的文件生成资源导入；`app/utils/recipe-images.ts` 据此将本地路径解析为 Vite 构建资源 URL。未使用的 Wiki 图片继续归档，不进入发布产物；开发时修改候选清单后重启 `pnpm dev` 以重新生成导入。页面不热链第三方图片。结果中的配图延迟加载，详情立即加载，固定宽高比避免跳动；加载失败保留占位和配方入口。
- 关于页简述配图来源与致谢；逐菜候选状态、原文件、异名／共用图形／英文条目状态与核对备注保留在本地清单，详情只显示配图。配方来源仍指用户附件，配图来源不能冒充原帖或游戏内验证。

配图的文件、链接和候选关系在来源清单中维护，显示行为与校验边界由本节维护。增改素材时同步核对来源清单、原文件与必要显示区域；单元测试随 `pnpm check` 校验 90 条配图延续、4 条新候选、同一原图的多个区域及原文件哈希。

## 菜品品质展示

品质读取[独立资料与约定](../recipes.md#菜品品质)。当前优先读取明天菜名格底色，空白或未收录时参考小铭；两图均缺依据的保持未知。保持菜品品质、图片分区、食材品质和效果阶级的区别。

- 图标、列表与详情共用 `RecipeQualityBadge`，显示蓝色／紫色／金色品质及文字提示，不能仅靠颜色区分。98 道有品质底色，竹香苹果冰采用明天紫底，甜饼果茶显示“品质待确认”；此前六条异名配图的候选状态仍在本地来源清单中保留。
- `RecipeImage` 新增可选 `quality` 参数，为 Wiki 透明 PNG 提供对应品质底色；未知品质保持中性背景。TapTap JPEG 原字节和现有显示区域不变，原图圆底继续保留。三个什锦饮、三个砂锅和三个烧烤可通过底色及文字区分。
- 品质依据保留在本地资料中，关于页仅说明用到的来源；详情不另设品质依据区域。来源篇目、图片序号、行号、观察底色、候选原因和原图／原帖链接均可在本地品质资料中追溯。
- 颜色只作为品质标签，不创造正式档位名称；不依赖菜名“梦幻”等前缀推断，也不根据力气或特殊效果阶级填值。原始配方及历史记录未改写。

## 组件边界

补充核对沿用现有组件合同：`RecipeList`、`IngredientSlots`、`RecipeDetails` 消费 `currentRecipes`，不修改基线转录。用户逐项决定在共享读取层应用，食材名、待确认提示、品质和搜索均读取同一采用值，详情不恢复来源面板。`RecipeEffectEvidence` 仅接收 `recipe`，通过计算属性读取效果作用或自由烹饪限制；父组件统一显示效果阶级、有效次数／时长及概率说明，不重复显示数值。原始截图、核对状态与新旧差异保留在资料目录和共享数据中，详情不展示来源、核对或证据组件。主体图包含词条列，已有菜采用明天词条；小铭补充的五道菜无词条，保持未说明。秘制菜获取方式显示原图友邻／任务原文。增益有效量按当前效果名称与阶级关联独立游戏截图或文字确认，不沿用被替换来源的数值。
