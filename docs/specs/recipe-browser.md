# 本地菜谱速查页面

页面入口为 `/`，沿用 Nuxt 4、Vue 3、TypeScript、Tailwind CSS 4、petit-ui 和 Reka UI，不增加数据库或运行时服务端 API。站点标题仍为 Petit。页面消费[已校验的菜谱数据](../recipes.md)，不修改原始转录来迎合展示。

## 关于与来源说明

`/about` 保留一段非官方手册简介、简短来源、原站链接、最新版图鉴、单独致谢和版权说明。菜谱资料来源与最新版图鉴放在同一区域；图片来源另设区域，说明 Wiki 菜品图标、TapTap 图鉴中的菜品区域及品质颜色依据，并集中提供图片来源链接。特别致谢单独感谢明天攻略组、Petit Planet Wiki 社区和 TapTap 作者阿Zz，署名读取现有清单。版权文案说明权利归属、尊重原创及侵权反馈后的核实处理，不宣称已经获得授权或保证不侵权。

当前只展示 2026-09-24 图鉴缩略图，点击打开原尺寸 JPEG，日期标注为图片日期。页面移除旧版入口、分区及品质统计、详细阅读规则；旧版图片和转录留在仓库用于追溯，不再打包到站点资源。菜谱详情仍保留逐项来源、候选与品质依据。

共用导航和页脚提供关于入口。详情的 `/about#<sourceId>` 定位到最新版图鉴，`/about#dish-quality` 定位到简短配图与品质来源说明，支持直接访问及刷新。首页与详情不增加明天攻略组署名文案，站点标题仍为 Petit。

两图差异、旧版 90 条快照及延续关系见[新版转录报告](../references/recipes/tomorrow-2026-09-24.md)。

## 内容与交互

视觉使用 petit-ui 的奶油纸色、深褐文字和金黄选择状态，默认以图标网格展示菜谱，也可切换为连续配方列表。筛选反馈、配方悬停和详情面板开合采用短促过渡；减少动态效果设置下关闭动效。

桌面保留筛选侧栏，窄屏将筛选收起为可展开区域，优先露出搜索与菜谱结果。

- 主搜索框统一查找菜名与食材原文，按关键词包含关系匹配，空格分隔的多个词需要同时命中。候选食材仍可查到，结果中的待确认状态保留；不推断食材类别成员关系或库存是否足够制作。
- 桌面侧栏与窄屏展开面板共用同一筛选组件，只保留图片分区和烹饪方式，支持与主搜索组合。图片分区不称为游戏内菜品等级。
- 旧链接中的单值或重复 `ingredient` 参数合并为主搜索框中的可见关键词，去除重复词和空项；兼容后使用相同的关键词搜索语义。下一次搜索、筛选或重置时写入 `q` 并清除旧参数，避免控件移除后仍保留隐藏条件。
- 可按原图顺序或已知力气升降序排列；未知力气始终位于末尾。
- 搜索、分区、方式与排序写入 URL 查询参数，支持刷新和浏览器导航。SSG 水合后再应用查询参数，避免静态 HTML 与客户端首帧不一致；初始化完成前禁用依赖脚本的控件，避免首次输入或点击丢失。搜索使用 Vue 原生 `v-model`，中文输入组合期间不更新筛选。
- 连续操作合并尚未完成路由更新的筛选请求，避免切换分区后立即搜索时沿用旧分区。
- 结果工具栏提供“图标／列表”视图切换，按钮有选中状态和可访问名称，初始化前禁用。每次进入或刷新页面默认图标视图；视图是当前页面的显示状态，不写入 URL，也不计入筛选数量。切换保留搜索、筛选、排序和结果顺序；清除筛选不改变当前视图。
- 图标视图突出大图与品质底色，显示完整菜名、分区、品质文字、待确认状态、烹饪方式和力气。桌面按可用宽度排列，手机为两列；食材与效果通过同一详情入口查看。两种视图共用候选配图、图片失败占位和详情交互，不复制另一份菜谱对应关系。
- 列表显示菜品缩略图、原文、保留重复项的食材、烹饪方式、力气、效果或产出。食材槽位按[食材品质要求](../recipes.md#食材品质要求)显示底色及“需紫色／金色品质”文字；候选和未知项继续保留独立提示，无底色不补猜品质。
- 点击配方打开 Reka UI 模态详情，支持 Escape、焦点约束和关闭后返回触发按钮。
- 详情显示菜品大图，保留特殊效果阶级、概率语义、词条、玩家限制、核对备注、原图视觉线索及分区／行号。原图行可按原尺寸横向查看，并可打开完整附件；食材底色按用户补充说明标注品质需求，颜色与加粗折叠说明保留规则原话与日期。加粗不作为品质依据，菜品品质继续读取下节的独立资料。
- 没有匹配时显示当前筛选造成的空状态和清除操作。

## 菜品配图

94 条记录均有候选配图：87 条使用 Wiki 原始 PNG，7 条使用六张 TapTap 完整攻略 JPEG 中的对应区域。两类原文件仍按[素材索引](../references/recipes/dish-image-candidates.md)分目录存放，图片显示不改变配方事实与游戏验证状态。

- `shared/recipes/images.ts` 从 Wiki 与 TapTap 清单读取候选，经 Zod 校验；旧版候选按菜谱的 `previousRecipeId` 延续，新候选直接引用当前 ID。清单保留原始核对位置，不按新的行号配图；不另存第二份菜谱与文件的对应表。
- 新增的梦幻金玉满堂饭、梦幻草莓奶蛋糕、梦幻星莓漫游派、梦幻番茄汤汁面使用已核对的 TapTap 同名图标区域，保留候选状态和图中行号。
- TapTap 清单的 `targetRecipes[].displayRegion` 是原图像素坐标 `{ x, y, width, height }`，左上角为原点，仅用于 CSS 显示范围。一张原图可关联多道菜，七个区域均为 150 × 150；原 JPEG 没有裁切、重绘或覆盖。详情可打开带作者署名的完整攻略图。
- `modules/recipe-image-assets.ts` 在 Nuxt 准备与构建时，按 `shared/recipes/images.ts` 中当前候选使用的文件生成资源导入；`app/utils/recipe-images.ts` 据此将本地路径解析为 Vite 构建资源 URL。未使用的 Wiki 图片继续归档，不进入发布产物；开发时修改候选清单后重启 `pnpm dev` 以重新生成导入。页面不热链第三方图片。结果中的配图延迟加载，详情立即加载，固定宽高比避免跳动；加载失败保留占位和配方入口。
- 关于页简述配图来源，详情单列候选状态、配图来源、原文件入口、异名／共用图形／英文条目状态与原有核对备注。配方来源仍指用户附件，配图来源不能冒充原帖或游戏内验证。

配图的文件、链接和候选关系在来源清单中维护，显示行为与校验边界由本节维护。增改素材时同步核对来源清单、原文件与必要显示区域；单元测试随 `pnpm check` 校验 90 条配图延续、4 条新候选、同一原图的多个区域及原文件哈希。

## 菜品品质展示

品质读取[独立资料与约定](../recipes.md#菜品品质)，以 TapTap 菜品图标底色为观察依据，以用户对颜色含义的说明为解释依据。保持菜品品质、图片分区、食材品质和效果阶级的区别。

- 图标、列表与详情共用 `RecipeQualityBadge`，显示蓝色／紫色／金色品质及文字提示，不能仅靠颜色区分。6 道异名对应显示“（候选）”，竹香苹果冰显示“品质待确认”。
- `RecipeImage` 新增可选 `quality` 参数，为 Wiki 透明 PNG 提供对应品质底色；未知品质保持中性背景。TapTap JPEG 原字节和现有显示区域不变，原图圆底继续保留。三个什锦饮、三个砂锅和三个烧烤可通过底色及文字区分。
- `RecipeQualityDetails` 接收同一品质记录，展示来源篇目、图片序号、行号、观察底色、候选原因和原图／原帖链接。`/about#dish-quality` 简述 TapTap 品质来源；用户确认、数量和状态的完整记录保留在品质资料与本规格，逐菜候选说明留在详情。
- 颜色只作为品质标签，不创造正式档位名称；不依赖菜名“梦幻”等前缀推断，也不根据力气或特殊效果阶级填值。原始配方及历史记录未改写。

## 组件边界

| 文件／组件                                    | 责任与数据合同                                                             |
| --------------------------------------------- | -------------------------------------------------------------------------- |
| `app/pages/index.vue`                         | 页面组合入口，仅挂载速查功能。                                             |
| `app/pages/about.vue`                         | 关于页组合入口，仅挂载资料说明内容。                                       |
| `app/layouts/default.vue`                     | 共用跳转正文入口、站点页头、页面插槽与页脚。                               |
| `SiteHeader` / `SiteFooter`                   | 共用站点标识与导航；内部链接使用 NuxtLink。                                |
| `AboutContent` / `AboutSources`               | 关于页简介、分开的菜谱与图片来源、最新版图鉴、单独致谢与版权说明。         |
| `RecipeBrowser`                               | 组合筛选、结果与详情，管理默认图标视图、当前详情与焦点恢复。               |
| `RecipeFilters`                               | 接收筛选值及数量，展示分区与烹饪方式，发出筛选补丁和重置事件。             |
| `RecipeViewToggle`                            | 接收显示模式与禁用状态，通过 `v-model` 切换图标／列表视图。                |
| `RecipeList`                                  | 接收结果与显示模式，共用数据展示图标网格或配方行，发出所选记录与触发元素。 |
| `IngredientSlots`                             | 接收菜谱，按有序槽位展示原文、食材品质要求与待确认状态。                   |
| `RecipeImage`                                 | 接收本地配图与菜名，共用缩略图／大图显示、攻略图区域定位与失败占位。       |
| `RecipeQualityBadge` / `RecipeQualityDetails` | 接收独立品质记录，分别显示可访问的品质文字及完整来源依据。                 |
| `RecipeDetails`                               | 接收菜谱与开关状态，展示完整转录、来源与核对信息，发出开关及焦点恢复事件。 |
| `useRecipeBrowser`                            | 从 URL 派生筛选与结果，合并连续操作并处理 URL 更新。                       |
| `app/utils/recipe-sources.ts`                 | 仅打包当前图鉴并按来源附件路径解析 URL，历史图保留在资料目录。             |
| `app/utils/recipes.ts`                        | 纯筛选、排序与显示语义，供页面与回归测试共用。                             |
