# 本地菜谱速查页面

页面入口为 `/`，沿用 Nuxt 4、Vue 3、TypeScript、Tailwind CSS 4、petit-ui 和 Reka UI，不增加数据库或运行时服务端 API。站点名称仍为 Petit。页面消费[已校验的菜谱数据](../recipes.md)，不修改原始转录来迎合展示。

## 站点定位与标识

Petit 定位为非官方的《星布谷地》资料站，为菜谱以外的内容留出空间。全站页眉、页脚和关于页使用“资料手册”，浏览器标题保留 Petit，站点描述说明目前提供菜谱速查。品牌使用透明底的扁平矢量小星球：上半部草地带陨石坑，下半部暖黄地面点缀巧克力豆以承接曲奇意象，中间由波浪形蓝色河流分隔。页眉与 SVG favicon 直接读取 `public/brand-mark.svg`，16／32 px PNG favicon 由同一源文件导出，所有图标保持相同的点缀。设计取舍、颜色与导出方式见[品牌素材记录](../references/branding/cake-planet.md)。

首页目前继续提供菜谱速查，导航保留“菜谱”和“关于”。页脚并列展示“关于与信息来源”和 GitHub 仓库链接；仓库地址由 `shared/site.ts` 的 `repositoryUrl` 维护，外链在新标签页打开。菜谱栏目内的标题、搜索提示与烹饪方式图标继续准确描述当前功能。关于页返回入口称为“返回首页”；新增其他内容栏目时再评估首页组织和路由调整。

## 页面元数据与分享预览

`shared/site.ts` 维护站点名称、默认正式地址 `https://petit.eruoo.dev`、默认标题与描述、关于页文案和分享图声明。该地址由用户确认，站点尚未部署。各页面调用 `app/composables/useSiteSeo.ts`，使用 [Nuxt 的 `useSeoMeta` 与 `useHead`](https://nuxt.com/docs/4.x/getting-started/seo-meta) 为静态 HTML 和客户端导航统一生成元数据。首页标题为“Petit · 星布谷地资料手册”，关于页为“关于 Petit · 星布谷地资料手册”。普通 description、Open Graph 与 Twitter/X 的标题和描述随页面一致更新。

Open Graph 提供 `og:title`、`og:description`、`og:type=website`、`og:site_name=Petit`、`og:locale=zh_CN`、`og:url` 及图片地址、类型、尺寸和替代文字。Twitter/X 使用 `summary_large_image`，共用页面标题、描述、图片与替代文字。图片字段遵循 [Open Graph 的结构化图片属性](https://ogp.me/#structured)。没有对应的社交账号配置，因此不声明账号归属。

`NUXT_PUBLIC_SITE_URL` 可在构建时覆盖默认正式地址，不能含用户名、密码、子路径、查询参数或片段。canonical 与 `og:url` 只包含该域名和规范化页面路径，去除尾部斜杠（首页保留 `/`），不包含搜索、排序、视图等展示参数。`og:image` 和 `twitter:image` 指向同域的绝对地址 `/og-image.png`。显式设置空字符串时，继续生成标题、描述和非地址类分享标签，省略 canonical、页面地址及图片标签；覆盖域名后须重新构建，步骤见[开发指南](../development.md#分享元数据与站点域名)。

首页与关于页共用 1200 × 630 的静态 PNG 分享图，使用奶油色背景、站点名称、资料手册定位和品牌小星球，注明目前提供菜谱速查。图片不依赖运行时生成服务；原图与重新导出方式见[品牌素材记录](../references/branding/cake-planet.md#分享图)。

图鉴预览直接接入 Viewer.js，不增加 Vue 封装依赖。核心仅在首次点击时动态加载，退出关于页销毁实例；静态页面和脚本不可用时仍保留原图链接。修饰键点击保留浏览器打开链接的行为，加载失败显示原图入口提示；预览图片本体失败时立即关闭空白弹层并返回触发位置，仍可打开另一张图或在网络恢复后重试。关闭或切图取消旧图片请求时不显示失败提示。预览支持 Esc 关闭、Tab 循环、键盘按钮操作与关闭后返回触发位置；跳过开场过渡，确保预览出现时即可关闭，其他动画尊重减少动态效果设置。为避免阅读大表格时误切图，触摸拖动和滚轮不切图，使用上一张／下一张按钮或左右方向键切换，首尾不循环。

共用导航和页脚提供关于入口。关于页支持直接访问及刷新；料理详情不再提供来源跳转或证据入口。首页与详情不增加明天攻略组署名文案，站点标题仍为 Petit。

## 内容与交互

视觉使用 petit-ui 的奶油纸色、深褐文字和金黄选择状态，默认以图标网格展示菜谱，也可切换为连续配方列表。搜索反馈、配方悬停和详情面板开合采用短促过渡；减少动态效果设置下关闭动效。

所有屏宽在统一搜索框上方显示菜谱分类，结果使用主内容完整宽度；不提供方式、食材、词条筛选面板或“搜索／筛选”模式切换。菜谱分类取自原图分区，继续在结果与详情中展示，不称为游戏内菜品等级。

- 分类为“全部、简单菜、招牌菜、宴客菜、自由烹饪、秘制菜、奇迹盛宴”七个单选项，默认全部，与关键词取交集。桌面一排，600 px 及以下三列自动换行，与搜索框间隔 12 px；使用原生单选控件，支持方向键、焦点提示和初始化前禁用。切换分类保留关键词、排序与视图；选择“全部”仅取消分类限制，搜索框的清空按钮仅清除关键词。
- 主搜索框统一查找菜名、食材原文、已录入的料理词条与烹饪方式。菜名、食材和方式按关键词包含关系匹配，例如“榨汁”可命中“榨汁机”；词条支持部分文字匹配，例如“饮”可命中“饮品”，输入完整词条时优先精确匹配，避免仅因“荤素菜”包含“素菜”而误命中。空格分隔的多个词需要同时命中，可分别命中不同字段，例如“草莓 小麦 甜点 烤箱”或“榨汁机 饮 奶”；候选食材仍可查到，结果中的待确认状态保留，待确认或未说明的词条与烹饪方式不作为确定值参与搜索。不推断食材类别成员关系或库存是否足够制作。
- 旧链接中的单值或重复 `ingredient` 参数延续已有兼容规则，合并为搜索框中的可见关键词，去除重复词和空项。已停用的 `mode`、`region`、`method`、`tag`、`ingredients` 参数直接忽略，不转成额外条件。下一次切换分类、编辑、清空搜索或排序时统一清除这些旧参数，仅保留当前 `category`、`q`、`sort` 及无关参数。
- 可按原图顺序或已知力气升降序排列；未知力气始终位于末尾。
- 分类、搜索词与排序写入 `category`、`q`、`sort` URL 查询参数，支持刷新和浏览器导航。分类采用 `simple`、`signature`、`guest`、`free`、`neighbor`、`miracle`，全部时省略参数，非法值回退全部；旧 `region` 参数继续忽略。SSG 水合后再应用查询参数，避免静态 HTML 与客户端首帧不一致；初始化完成前禁用依赖脚本的控件，避免首次输入或点击丢失。搜索使用 Vue 原生 `v-model`，中文输入组合期间不更新结果。
- 分类、连续输入和排序合并尚未完成的路由请求，避免丢失最近输入。查询参数更新保留当前锚点，从“回到搜索”进入后输入或清空不会滚回页顶。纯空白查询显示所选分类的全部菜谱，不显示“搜索结果”标记；保留输入中的分隔空格，方便继续输入下一个关键词。
- 结果工具栏提供“图标／列表”视图切换，按钮有选中状态和可访问名称，初始化前禁用。每次进入或刷新页面默认图标视图；视图是当前页面的显示状态，不写入 URL。切换保留分类、搜索、排序和结果顺序；清空搜索或重置条件不改变排序或当前视图。
- 图标视图突出大图与品质底色，显示完整菜名、分区、品质文字、待确认状态、烹饪方式和力气。桌面按可用宽度排列，手机为两列；食材与效果通过同一详情入口查看。两种视图共用候选配图、图片失败占位和详情交互，不复制另一份菜谱对应关系。
- 列表显示菜品缩略图、原文、保留重复项的食材、烹饪方式、力气、效果或产出。食材槽位按[食材品质要求](../recipes.md#食材品质要求)显示底色及“需紫色／金色品质”文字；候选和未知项继续保留独立提示，无底色不补猜品质。
- 点击菜谱卡片或列表项打开 Reka UI 模态详情，支持 Escape、焦点约束和关闭后返回触发按钮，关闭弹窗保留当前搜索、分类、排序和视图。菜谱只通过弹窗查看，不提供重复的“完整配方”入口或独立详情页。
- 详情显示菜品大图、分区、菜品品质、有序食材及品质需求、烹饪方式、力气、词条、特殊效果名称与阶级、作用和次数／时长。保留问号食材、未知值和制作限制；自由烹饪显示明天补充资料中的产出概率，具体效果未说明。配方来源、待核对信息、新旧图鉴对照、原图行与视觉线索、配图来源、品质依据及增益截图均不在详情展示；这些资料继续本地归档与校验。
- 列表与详情中，已有配方、效果栏空白或斜杠的非自由烹饪菜品按用户约定显示“无特殊效果”，不再追加“未说明特殊效果”。这只是展示文案，来源空白仍保留 `not-stated`，斜杠保留 `unresolved`；未知、待确认效果与自由烹饪产出继续分别表达。轰炸大菇肉采用煮锅和 90 力气，食材与效果保留问号；云朵小饼干使用烤箱，其余未知项不补猜。奇迹盛宴显示对应词条、180 力气及概率产出说明，食材与厨具未说明，不显示“0 个食材槽位”。
- 没有匹配时提示切换分类或更换菜名、食材、词条、烹饪方式，并提供“清除搜索条件”，同时重置分类与关键词。重置后显示全部菜谱，保留排序与视图，已停用的旧参数不会重新生效。

- `modules/recipe-image-assets.ts` 在 Nuxt 准备与构建时，按 `shared/recipes/images.ts` 中当前候选使用的文件生成资源导入；`app/utils/recipe-images.ts` 据此将本地路径解析为 Vite 构建资源 URL。未使用的 Wiki 与 TapTap 图片继续归档，不进入发布产物；开发时修改候选清单后重启 `pnpm dev` 以重新生成导入。页面不热链第三方图片。结果中的配图延迟加载，详情立即加载，固定宽高比避免跳动；加载失败保留占位和配方入口。
- 关于页简述配图来源与致谢；逐菜候选状态、原文件、异名／共用图形／英文条目状态与核对备注保留在本地清单，详情只显示配图。配方来源仍指用户附件，配图来源不能冒充原帖或游戏内验证。

配图的文件、链接和候选关系在来源清单中维护，显示行为与校验边界由本节维护。增改素材时同步核对来源清单、原文件与必要显示区域；单元测试随 `pnpm check` 校验既有 94 条配图延续、七道秘制菜补图后的覆盖、四道高清图优先采用、剩余攻略区域及原文件哈希。

## 组件边界

补充核对沿用现有组件合同：`RecipeList`、`IngredientSlots`、`RecipeDetails` 消费 `currentRecipes`，不修改基线转录。用户逐项决定在共享读取层应用，食材名、待确认提示、品质和搜索均读取同一采用值，详情不恢复来源面板。`RecipeEffectEvidence` 仅接收 `recipe`，通过计算属性读取效果作用或自由烹饪限制；父组件统一显示效果阶级、有效次数／时长及概率说明，不重复显示数值。原始截图、核对状态与新旧差异保留在资料目录和共享数据中，详情不展示来源、核对或证据组件。词条统一读取明天 9/29，原有八道缺词条的秘制菜均已补齐；云朵小饼干的词条仍为问号。秘制菜获取方式显示原图友邻／任务原文。增益有效量按当前效果名称与阶级关联独立游戏截图或文字确认，不沿用被替换来源的数值。
